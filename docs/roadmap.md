# 开发里程碑与完成标准

## 0. 可复现的软件基线（当前）

- 独立源码可生成 Cortex-M0+ ELF/raw；链接器与向量检查约束地址范围。
- SPI NOR 只读驱动、Si4732 探测与 FM 接收命令、可观察的 RAM 诊断接口。
- `0.2.0-exp` 增加 SPI1 LCD/RGB PWM、独立 1024 B 诊断帧缓冲、可选矩阵/PTT 输入、ABI 2 状态；矩阵默认关闭以不主动占用 PA14/SWCLK。
- 包装格式由固定官方样本的 CRC、SHA-256 和逐字节回环测试支撑。
- 主机单元测试与 CI 可以复现。测试通过只表明这些软件检查通过。
- 已恢复信道/VFO/属性/扫描布局，并独立实现保留未知字节的离线工具；原厂加载、保存、删除和格式化函数可用固定样本重放。
- 已恢复电脑原始存储读写协议、USB 描述符、CRC/XOR/门控语义，完成合成 NOR 的实际写入再读回；普通 CI 不下载厂商样本。
- 已实际执行 NOR 更新和 RF 三线 GPIO 函数，整理官方 APK 设置地图及版本冲突。详见 [仿真记录](emulation.md) 与 [设置地图](settings-map.md)。
- 已执行 14 个 LCD/PWM 场景、53 个按键/事件/UI/延时场景；单独审计 K8/K82/UV5 与 CPS 实际调用链。用户确认 PY32F071 系列、25Q32 4 MiB，来源与实测边界分别记录。

## 0.1. 读写频工具的下一阶段

取得同一硬件和固件版本的外部 NOR 备份、官方 CPS 正常 USB 抓包，核验 hello/RTC/session 与门控状态的完整生命周期。交叉验证动态频段、未知字节、APRS 重叠字段及不同软件版本。随后实现可审查的读取、修改差分、状态确认与读回比较流程；当前帧草稿和 CPU 仿真尚不代表完成在线写频。

## 1. 已记录的实机启动

在用户确认 MCU 系列与 NOR 密度基础上，需要指定硬件版本的完整器件后缀/封装、板号、供电与复位控制、可用调试接点、已核实的备份与恢复步骤。记录 bootloader 交接时的 RCC、时钟实测值、watchdog 状态和向量基址。完成标准是诊断阶段 4 持续运行，UID/JEDEC/Si4732 信息可重复读取，失败路径无无限等待。

## 2. 可操作的显示与键盘

已从实际调用链确定 LCD SPI1/128×64 页格式、背光三路 PWM、矩阵与 PTT、原厂去抖和主要键码语义，独立诊断页与驱动已实现。下一步以同型号板卡核验排线/焊盘、控制器唯一型号、像素方向、供电/RESET 和 PA14 复用，随后实现频率编辑、可导航菜单及兼容的长按交互。完成标准是设备本机可导航，无调试器也能读到状态和错误；当前主机预览不满足实机完成标准。

## 3. 接收机

确认主对讲 RF 芯片及寄存器、音频路径、天线切换、静噪和校准数据。根据硬件版本区分主接收链和可选 Si4732。完成标准包括准确频率、接收音频、模式切换和稳定性测量；不能用“发送了调谐命令”代替接收测试。

## 4. 设置保存与可靠更新

先确认外部 Flash 真实分区、校准和用户数据格式，再设计新的带版本/校验的设置区与掉电恢复。单独验证 bootloader 的长度检查、擦除范围、失败恢复和各硬件版本差异。在这些证据建立前不增加写入/擦除接口到默认诊断应用。

## 5. 完整对讲与附加功能

在主 RF 硬件映射和校准齐备后开发功率、频偏、发射定时、保护状态等，并进行设备测量。GPS/APRS、USB、扫描、信道管理及其他扩展按具体硬件配置逐步补齐。稳定发行版本需要明确的支持机型矩阵和测试记录。
