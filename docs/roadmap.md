# 开发里程碑与完成标准

## 0. 可复现的软件基线（当前）

- 独立源码可生成 Cortex-M0+ ELF/raw；链接器与向量检查约束地址范围。
- SPI NOR 只读驱动、Si4732 探测与 FM 接收命令、可观察的 RAM 诊断接口。
- 包装格式由固定官方样本的 CRC、SHA-256 和逐字节回环测试支撑。
- 主机单元测试与 CI 可以复现。测试通过只表明这些软件检查通过。

## 1. 已记录的实机启动

需要指定硬件版本的 MCU/Flash 丝印照片、供电与复位控制、可用调试接点、已核实的备份与恢复步骤。记录 bootloader 交接时的 RCC、时钟实测值、watchdog 状态和向量基址。完成标准是诊断阶段 4 持续运行，UID/JEDEC/Si4732 信息可重复读取，失败路径无无限等待。

## 2. 可操作的显示与键盘

从实际调用链确定 LCD 类型和总线、背光、按键矩阵及去抖。先显示诊断页，再提供频率编辑、菜单和状态显示；为每项硬件映射留下样本地址或实测证据。完成标准是设备本机可导航，无调试器也能读到状态和错误。

## 3. 接收机

确认主对讲 RF 芯片及寄存器、音频路径、天线切换、静噪和校准数据。根据硬件版本区分主接收链和可选 Si4732。完成标准包括准确频率、接收音频、模式切换和稳定性测量；不能用“发送了调谐命令”代替接收测试。

## 4. 设置保存与可靠更新

先确认外部 Flash 真实分区、校准和用户数据格式，再设计新的带版本/校验的设置区与掉电恢复。单独验证 bootloader 的长度检查、擦除范围、失败恢复和各硬件版本差异。在这些证据建立前不增加写入/擦除接口到默认诊断应用。

## 5. 完整对讲与附加功能

在主 RF 硬件映射和校准齐备后开发功率、频偏、发射定时、保护状态等，并进行设备测量。GPS/APRS、USB、扫描、信道管理及其他扩展按具体硬件配置逐步补齐。稳定发行版本需要明确的支持机型矩阵和测试记录。
