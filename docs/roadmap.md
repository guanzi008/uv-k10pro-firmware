# 开发里程碑与完成标准

## 0. 可复现的软件基线（当前）

- 独立源码可生成 Cortex-M0+ ELF/raw；链接器与向量检查约束地址范围。
- SPI NOR 只读驱动、既有 Si4732 探测与 FM 接收命令、可观察的 RAM 诊断接口。保留 Si4732 实现；它不构成当前板卡上 Si4732 存在或与 BK1080 共存的证明。
- `0.2.0-exp` 增加 SPI1 LCD/RGB PWM、独立 1024 B 诊断帧缓冲、可选矩阵/PTT 输入、ABI 2 状态；矩阵默认关闭以不主动占用 PA14/SWCLK。
- 包装格式由固定官方样本的 CRC、SHA-256 和逐字节回环测试支撑。
- 主机单元测试与 CI 可以复现。测试通过只表明这些软件检查通过。
- 已恢复信道/VFO/属性/扫描布局，并独立实现保留未知字节的离线工具；原厂加载、保存、删除和格式化函数可用固定样本重放。
- 已恢复电脑原始存储读写协议、USB 描述符、CRC/XOR/门控语义，完成合成 NOR 的实际写入再读回；普通 CI 不下载厂商样本。
- 已实际执行 NOR 更新和 RF 三线 GPIO 函数，整理官方 APK 设置地图及版本冲突。详见 [仿真记录](emulation.md) 与 [设置地图](settings-map.md)。
- 已执行 14 个 LCD/PWM 场景、53 个按键/事件/UI/延时场景；单独审计 K8/K82/UV5 与 CPS 实际调用链。用户确认 PY32F071 系列、25Q32 4 MiB，来源与实测边界分别记录。
- 2026-11-27 用户补充 BK4829、CS6150XC，明确收音机为 BK1080、蓝牙为 PHY6235SC/BLE 5.4/RISC-V；[原始报告](evidence/owner-hardware-20261127.json)与已有仿真分开记录。CS6150XC 功能未知；[PHY6235 官方家族页](https://www.phyplusinc.com/product_detail/17.html)佐证 BLE 5.4/RISC-V，SC 后缀封装和存储容量待核实。详见 [型号审计](model-identity.md)及 [蓝牙硬件说明](bluetooth-hardware.md)。

## 0.1. 读写频工具的下一阶段

取得同一硬件和固件版本的外部 NOR 备份、官方 CPS 正常 USB 抓包，核验 hello/RTC/session 与门控状态的完整生命周期。交叉验证动态频段、未知字节、APRS 重叠字段及不同软件版本。随后实现可审查的读取、修改差分、状态确认与读回比较流程；当前帧草稿和 CPU 仿真尚不代表完成在线写频。

广播预置的存储读写与接收芯片的寄存器调谐分别核对。以用户确认的 BK1080 为当前板卡身份线索，追踪官方应用/CPS 的实际分支、原固件 FM 调用点和预置区；保留 CPS 默认选择 Si4732 的历史事实及相关代码，不因默认选项推定焊接配置。蓝牙路径结合 PHY6235SC 的器件报告继续核对 K8 会话、实际服务/特征与主 MCU 数据通路；BLE 5.4 家族规格本身不证明这些应用层接口。

## 1. 已记录的实机启动

在用户确认 MCU 系列与 NOR 密度基础上，需要指定硬件版本的完整器件后缀/封装、板号、供电与复位控制、可用调试接点、已核实的备份与恢复步骤。补核 BK4829、BK1080、PHY6235SC 的板级连接，以及 CS6150XC 的厂商与功能；PHY6235 家族资料不能代替 SC 后缀的封装、存储容量和引脚资料。记录 bootloader 交接时的 RCC、时钟实测值、watchdog 状态和向量基址。完成标准是诊断阶段 4 持续运行，UID/JEDEC 和该硬件版本已核实接收器件的诊断信息可重复读取，失败路径无无限等待；Si4732 信息读取只在确认配有该器件的配置中作为完成条件。

## 2. 可操作的显示与键盘

已从实际调用链确定 LCD SPI1/128×64 页格式、背光三路 PWM、矩阵与 PTT、原厂去抖和主要键码语义，独立诊断页与驱动已实现。下一步以同型号板卡核验排线/焊盘、控制器唯一型号、像素方向、供电/RESET 和 PA14 复用，随后实现频率编辑、可导航菜单及兼容的长按交互。完成标准是设备本机可导航，无调试器也能读到状态和错误；当前主机预览不满足实机完成标准。

## 3. 接收机

基于用户报告的 BK4829，逐项核对主 RF 调用点、寄存器语义、音频路径、天线切换、静噪和校准数据。已有三线 GPIO 仿真提供 MCU 信号与事务线索，不能唯一识别芯片或证明其他 BK48xx 寄存器表兼容。依据同一板卡材料核验这些信号到 BK4829 的实际引脚连接。

以用户明确的 BK1080 收音机身份继续追踪 FM 初始化、调谐、搜台、静音和预置读写路径，补齐与主 MCU 的总线、控制线及音频连接。此前 Si4732 用户报告和现有驱动保留，按硬件版本核实其适用性；两颗广播接收芯片同板共存仍需独立证据。CS6150XC 保留完整标识并继续查证功能，不凭器件清单为其新建驱动或指定 GPIO。完成标准包括准确频率、接收音频、模式切换和稳定性测量；不能用“发送了调谐命令”代替接收测试。

## 4. 设置保存与可靠更新

先确认外部 Flash 真实分区、校准和用户数据格式，再设计新的带版本/校验的设置区与掉电恢复。单独验证 bootloader 的长度检查、擦除范围、失败恢复和各硬件版本差异。在这些证据建立前不增加写入/擦除接口到默认诊断应用。

## 5. 完整对讲与附加功能

在主 RF 硬件映射和校准齐备后开发功率、频偏、发射定时、保护状态等，并进行设备测量。针对用户报告的 PHY6235SC，先核对准确后缀、存储配置、与 MCU 的实际接口/引脚、供电与复位、原固件数据通路及官方应用的蓝牙连接行为，再实现对应通信功能；不从 BLE 5.4/RISC-V 家族规格直接推定板级 GPIO 或 K8 传输格式。GPS/APRS、USB、扫描、信道管理及其他扩展按具体硬件配置逐步补齐。稳定发行版本需要明确的支持机型矩阵和测试记录。
